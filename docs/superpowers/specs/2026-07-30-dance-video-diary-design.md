# 练舞视频日记 Android 首版设计规格

日期：2026-07-30

状态：已确认，待实施计划

目标平台：Android

产品定位：个人自用、本地优先的练舞视频整理与回顾工具

## 1. 背景与目标

用户通常先使用手机相机、微信等工具拍摄练舞视频，再从相册整理。首版不重复实现系统相机能力，而是集中解决以下问题：

1. 将分散在相册中的练舞视频可靠地导入 App。
2. 自动按练习日期归档。
3. 通过日历、标签、音乐和备注快速找到视频。
4. 使用镜像与变速功能进行基础回看。
5. 通过本地备份、回收站和可恢复的导入流程降低视频丢失风险。

首版的成功标准是：用户能够持续导入视频，并能在数秒内通过日期或标签找到过去的练习记录。

## 2. 已确认的产品原则

- Android 单平台，首版通过 APK 安装并个人使用。
- 不注册、不登录，不建立服务端。
- 视频与元数据默认只保存在本机。
- 导入时将视频复制到 App 专用目录，原相册文件不受影响。
- 导入后立即建立记录，不强制填写标签、标题或备注。
- 日历是默认首页，日期与标签整理是首要能力。
- 首版不实现 AB 循环；它属于后续的参考视频学习流程。
- 架构为参考视频、练习视频关联及对比功能预留扩展点。

## 3. 首版范围

### 3.1 包含

- 从 Android 系统照片选择器单选或多选视频。
- 将选中视频复制到 App 私有媒体目录。
- 自动读取拍摄时间、文件时间、时长、分辨率、文件大小和原文件名。
- 异步生成视频缩略图。
- 根据练习日期在月历中归档。
- 查看某日的独立日期详情页。
- 按日期倒序查看完整记录时间线。
- 添加内置舞种标签和自定义标签。
- 编辑音乐名称、艺人、BPM、备注、自评和收藏状态。
- 按日期、标签、音乐和收藏状态筛选。
- 搜索音乐、备注与自定义标签文本。
- 基础视频播放、进度拖动、镜像显示和播放速度调整。
- 批量选择记录。
- 删除到回收站、从回收站恢复、永久删除。
- 导出选中视频及 JSON 元数据。
- 完整 ZIP 备份与恢复。
- 查看 App 内视频存储占用。

### 3.2 不包含

- App 内摄像头录制。
- 录制暂停、继续和自动分段。
- AB 循环。
- 逐帧前进或后退。
- 两段视频并排、叠加或同步对比。
- AI 骨骼识别、动作评分或训练建议。
- Google Drive、其他云盘或自建云服务。
- 注册、登录和多用户。
- 每日提醒、桌面小组件和社交分享。
- iOS 适配和应用商店发布。

## 4. 后续演进方向

后续版本将引入两种视频角色：

- `practice`：用户自己的练习视频。
- `reference`：喜欢并准备学习或翻跳的参考视频。

参考视频可以关联多个练习视频。学习模式在此关系上增加：

- AB 循环和分段标记。
- 参考视频镜像、变速播放。
- 参考视频与练习视频的时间偏移。
- 并排或叠加对比。
- 对比截图。

首版数据库保留 `role` 字段，但导入记录默认设为 `practice`，界面不提供角色切换。

## 5. 页面与导航

底部主导航包含四个入口：

1. **日历**：默认首页。
2. **记录**：完整时间线、搜索与筛选。
3. **标签**：标签管理与按标签查看。
4. **设置**：存储、备份、恢复、回收站与应用信息。

### 5.1 日历首页

- 顶部显示当前月份，可切换月份。
- 显示本月练习天数、累计时长和当前连续记录天数。
- 有视频的日期显示视觉标记。
- 点击日期进入独立日期详情页。
- 页面保留明确的“导入视频”主操作按钮。

### 5.2 日期详情页

- 显示所选日期的视频数量和总时长。
- 以缩略图列表展示当天视频。
- 每项显示时长、标签、音乐或整理状态。
- 支持进入视频详情。
- 支持批量选择、修改日期、导出和删除。

### 5.3 记录页

- 所有视频按练习日期倒序分组。
- 支持搜索和组合筛选。
- 支持批量选择。
- 未添加标签和备注的视频显示“稍后整理”，但不阻止正常使用。

### 5.4 标签页

- 展示内置舞种和自定义标签。
- 内置舞种可排序但不能误删。
- 自定义标签可添加、改名和删除。
- 删除已使用的标签前显示受影响的视频数量；删除关联，不删除视频。
- 点击标签进入相关视频列表。

### 5.5 视频详情页

- 顶部为播放器。
- 播放器提供播放/暂停、进度拖动、镜像、静音和播放速度。
- 下方编辑练习日期、标签、音乐、备注、自评和收藏。
- 字段修改明确保存；离开未保存页面时提示。

### 5.6 设置页

- 显示 App 内视频、临时文件和数据库占用。
- 提供完整备份、恢复、选中记录导出和回收站入口。
- 提供默认镜像与默认播放速度设置。

## 6. 技术架构

### 6.1 技术选型

- Flutter + Material 3。
- 中文界面。
- Riverpod 管理页面状态和异步任务。
- Drift + SQLite 保存结构化数据并管理数据库迁移。
- Flutter 官方 `video_player` 实现首版播放能力。
- Android 系统照片选择器用于选取视频。
- Android Storage Access Framework 用于选择备份、恢复和导出位置。
- App 私有目录保存媒体文件；数据库只保存相对路径。

依赖版本在实施时基于当时稳定版统一锁定，不沿用原始 PRD 中已过时的固定版本。

### 6.2 模块边界

- `features/import`：选择视频、导入队列、进度与结果。
- `features/calendar`：月历、日期汇总和连续记录统计。
- `features/timeline`：时间线、搜索、筛选和批量选择。
- `features/tags`：标签管理与标签视频列表。
- `features/session`：视频详情与元数据编辑。
- `features/player`：播放器生命周期、镜像和速度。
- `features/backup`：导出、完整备份、校验与恢复。
- `features/trash`：回收站、恢复和永久删除。
- `core/database`：表结构、查询和迁移。
- `core/media`：文件复制、摘要、元数据、缩略图和存储统计。

各功能模块通过仓储接口访问数据库和媒体服务，页面不直接操作文件路径或 SQLite。

## 7. 数据模型

### 7.1 PracticeVideo

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PRIMARY KEY | 应用生成的稳定 UUID |
| role | TEXT | 首版固定为 `practice` |
| relative_path | TEXT UNIQUE NOT NULL | App 媒体目录内相对路径 |
| thumbnail_path | TEXT | 缩略图相对路径 |
| original_file_name | TEXT | 导入前文件名 |
| file_hash | TEXT NOT NULL | SHA-256 内容摘要 |
| file_size_bytes | INTEGER NOT NULL | 文件大小 |
| duration_ms | INTEGER | 视频时长 |
| width | INTEGER | 视频宽度 |
| height | INTEGER | 视频高度 |
| recorded_at | DATETIME NOT NULL | 用户可修改的归档日期时间 |
| metadata_recorded_at | DATETIME | 原始元数据中的拍摄时间 |
| imported_at | DATETIME NOT NULL | 导入完成时间 |
| music_title | TEXT | 音乐名称 |
| music_artist | TEXT | 艺人 |
| music_bpm | INTEGER | BPM |
| notes | TEXT | 备注 |
| energy_rating | INTEGER | 1–5，可空 |
| is_favorite | BOOLEAN NOT NULL | 收藏状态 |
| deleted_at | DATETIME | 非空表示在回收站 |
| created_at | DATETIME NOT NULL | 记录创建时间 |
| updated_at | DATETIME NOT NULL | 最后修改时间 |

对 `recorded_at`、`file_hash`、`is_favorite` 和 `deleted_at` 建立查询索引。

### 7.2 Tag

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PRIMARY KEY | 稳定 UUID |
| name | TEXT NOT NULL | 标签名称 |
| normalized_name | TEXT UNIQUE NOT NULL | 去空格、统一大小写后的去重值 |
| type | TEXT NOT NULL | `built_in` 或 `custom` |
| sort_order | INTEGER NOT NULL | 展示顺序 |
| created_at | DATETIME NOT NULL | 创建时间 |
| updated_at | DATETIME NOT NULL | 修改时间 |

### 7.3 VideoTag

| 字段 | 类型 | 说明 |
|---|---|---|
| video_id | TEXT | 外键，删除视频时级联删除 |
| tag_id | TEXT | 外键，删除标签时级联删除 |

`video_id + tag_id` 为联合主键，禁止重复关联。

### 7.4 AppSettings

键值式设置表保存默认镜像、默认播放速度、最近备份时间和界面偏好。设置值包含类型标识和架构版本，便于迁移。

### 7.5 ImportTask

保存批量导入中每个文件的状态：

- `pending`
- `copying`
- `processing`
- `completed`
- `failed`

任务记录包含来源 URI、临时文件路径、进度、错误类型和已生成的视频 ID。应用重启后根据任务状态继续处理或清理。

## 8. 日期规则

`recorded_at` 按以下顺序初始化：

1. 视频元数据中的原始拍摄时间。
2. Android 提供的媒体日期或文件修改时间。
3. 导入时间。

所有日期在数据库中保存带时区语义的 UTC 时间，在界面中转换为设备当前时区。用户修改练习日期后，日历和时间线立即重新归档；不修改底层视频文件时间。

## 9. 导入数据流

```text
系统照片选择器
→ 建立导入任务
→ 检查可用空间
→ 复制到 App 临时目录
→ 校验文件大小并计算 SHA-256
→ 检测重复视频
→ 读取元数据
→ 生成缩略图
→ 原子移动到正式媒体目录
→ 数据库事务写入记录与标签关联
→ 完成任务并刷新日历
```

### 9.1 重复视频

使用文件大小和 SHA-256 判断内容完全相同的视频。发现重复时：

- 不复制第二份。
- 不创建第二条记录。
- 提示现有视频所在日期，并允许直接打开。

文件名相同但摘要不同不视为重复。

### 9.2 批量处理

- 逐条提交结果，一条失败不回滚其他成功项。
- 界面显示总进度、当前文件和失败数量。
- 完成后展示成功、重复和失败清单。
- 失败项可单独重试。

## 10. 文件布局与生命周期

App 私有目录采用稳定结构：

```text
media/videos/<video-id>.<ext>
media/thumbnails/<video-id>.jpg
temp/imports/<task-id>/
database/
```

- 数据库只保存相对路径。
- 原始扩展名在兼容且安全时保留。
- 临时目录中的过期任务在应用启动后清理。
- 删除记录只处理 App 内副本，不修改相册原文件。

## 11. 删除与回收站

- 删除操作设置 `deleted_at`，记录与文件进入应用内回收站。
- 普通日历、时间线、标签统计和搜索排除回收站内容。
- 回收站默认保留 30 天。
- 用户可以恢复记录或永久删除。
- 永久删除同时删除 App 内视频、缩略图和数据库记录。
- 清空回收站前再次确认，并显示将释放的空间。

## 12. 备份、恢复与导出

### 12.1 完整备份

文件名格式：`dance-diary-backup-YYYYMMDD-HHmmss.zip`

```text
manifest.json
metadata.json
media/
  <video-id>.<ext>
```

- `manifest.json` 保存备份格式版本、应用版本、创建时间、文件清单、大小和 SHA-256。
- `metadata.json` 保存视频记录、标签、关联和设置。
- 缩略图不进入备份，恢复后重新生成。
- 备份写入临时目标并完整校验后，再提交到用户选择的位置。

### 12.2 恢复

1. 验证 ZIP 结构、格式版本、文件路径和文件摘要。
2. 在临时工作区解析元数据。
3. 检测与当前库重复的视频。
4. 复制缺失媒体并在数据库事务中合并记录。
5. 重新生成缩略图。
6. 全部关键步骤成功后提交恢复结果。

恢复失败不覆盖现有数据库，也不删除当前媒体。合并规则如下：

- 备份记录 ID 与当前记录 ID 相同且内容摘要相同：视为同一记录，不覆盖当前已编辑字段，只补充当前缺少的标签。
- 内容摘要相同但记录 ID 不同：复用已有媒体文件，不创建第二条视频记录，并补充当前缺少的标签。
- 记录 ID 相同但内容摘要不同：为备份记录生成新 ID，并作为独立视频恢复。
- 标签按规范化名称合并；同名标签不重复创建。

### 12.3 选中记录导出

导出 ZIP 包含被选中的视频文件和对应 JSON 元数据。该功能用于携带或分享部分记录，不等同于可完整恢复 App 状态的备份。

## 13. 异常处理

- **空间不足**：复制前拦截并显示所需空间、可用空间和清理入口。
- **来源权限失效**：标记当前项失败，允许重新选择文件。
- **损坏或不支持的视频**：在能安全复制时保留文件并标记元数据或播放失败，允许用户验证、导出或删除。
- **应用中断**：保留导入任务状态；下次启动恢复或清理。
- **缩略图失败**：不阻止记录建立，显示占位图并提供重试。
- **播放器初始化失败**：保留详情与导出能力，显示可理解的错误信息。
- **数据库写入失败**：不提交正式媒体文件；回滚事务并清理临时文件。
- **备份失败**：不留下伪装成成功备份的目标文件。
- **恢复失败**：保持恢复前数据不变。

## 14. 性能要求

- 文件复制、摘要计算、元数据读取和缩略图生成不得阻塞 UI。
- 时间线与日期列表使用分页或懒加载。
- 月历统计使用数据库聚合查询，不逐条加载视频对象。
- 缩略图按显示尺寸解码并使用缓存。
- 页面离开后及时释放播放器资源。
- 批量导入限制并发，避免同时解码多个大视频导致内存峰值。

## 15. 隐私与权限

- 不请求账户、位置、通讯录或网络上传权限。
- 仅在用户主动选择时读取选中的视频 URI。
- 媒体默认存放在 App 私有目录，其他应用不能直接浏览。
- 只有用户主动执行备份或导出时，才向用户选择的位置写入文件。
- 首版不采集遥测和使用数据。

## 16. 测试策略

### 16.1 单元测试

- 日期回退规则。
- 标签名称规范化和去重。
- 文件摘要与重复判定。
- 日历月统计与连续日期计算。
- 搜索、筛选和回收站排除逻辑。
- 备份清单生成与校验。

### 16.2 数据库测试

- 建表、约束、索引和迁移。
- 视频、标签与关联的增删改查。
- 修改练习日期后的统计更新。
- 软删除、恢复和永久删除。
- 恢复事务失败时回滚。

### 16.3 集成测试

- 单个和批量导入。
- 相机拍摄、微信保存、横屏、竖屏和不同分辨率视频。
- 重复导入、损坏文件、空间不足和导入中断。
- 镜像、静音、拖动和不同倍速播放。
- 完整备份后在空数据库中恢复，并核对记录数、文件摘要和元数据。

### 16.4 Android 实机验收

- 至少一台目标 Android 手机完成安装与权限验证。
- 导入 20 个以上不同来源视频，App 无崩溃。
- 冷启动后日历与时间线正确。
- 完整备份、清除 App 数据、重新安装后恢复成功。
- 恢复后视频可播放、标签可筛选、日期统计一致。

## 17. 实施分期

首版实施按风险优先：

1. 数据库、媒体目录和导入事务。
2. 月历、日期页和基础详情编辑。
3. 时间线、搜索、筛选和标签管理。
4. 基础播放器。
5. 回收站。
6. 备份、恢复和选中记录导出。
7. 性能优化与 Android 实机验收。

每一阶段必须保持数据库可迁移、现有记录可打开，并通过该阶段对应测试后再进入下一阶段。
